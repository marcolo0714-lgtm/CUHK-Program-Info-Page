# AGENTS.md — Rules for maintaining this project

## Never commit or push without explicit instruction
- The user will explicitly ask to commit or push. Do NOT do it unprompted.

## Multi-year support
- All generators accept `--year` (default `2025_26`) to target a specific admission year.
- Folder structure:
  ```
  minor_extraction/minor_html/{year}/        ← raw HTML from handbook
  minor_extraction/minor_json/{year}/        ← parsed JSON per minor
  minor_extraction/course_overrides/{year}.json
  site/{year}/index.html                     ← minor programme list
  site/{year}/checker.html                   ← interactive checker
  site/{year}/minors/*.html                  ← detail info pages
  site/checker_data.json                     ← course catalog (year-agnostic)
  site_tempdata/checker_minors_{year}.json   ← intermediate checker data
  ```
- The root `site/index.html` redirects to the newest year's index page.
- Each year's `index.html` and `checker.html` includes a year dropdown selector.

## Editing flow
- `site/{year}/checker.html` is GENERATED by `minor_planner/generate_checker_page.py` — edit the Python source, NOT the HTML.
- `site/{year}/minors/*.html` is GENERATED by `minor_extraction/generate_minor_site.py` — edit the Python source, NOT the HTML.
- `site/checker_data.json` is GENERATED by `minor_planner/generate_checker_data.py` — edit the Python source, NOT the JSON.
- After editing Python generators, always regenerate the output files.
- After editing `minor_extraction/minor_json/{year}/*.json`, regenerate `checker_data.json` then `checker.html`.
- `course_extraction/get_course_info.py` — only modify the scraper; the user runs scraping manually (takes hours).
- `course_extraction/tests/test_course_info.py` — run `pytest` to verify scraped course data integrity.

## Manual edits to JSON files
- Record all manual edits to `minor_extraction/minor_json/{year}/*.json` in `MANUAL_EDITS.md`.
- 11 files have `_auto_generated: false` and are skipped by `generate_minor_json.py` on regeneration.

## Regeneration commands
```powershell
# After editing resolve_course_descriptions.py (preserves manual entries automatically):
python minor_extraction/resolve_course_descriptions.py --apply --year 2025_26
# After editing source JSON or generate_checker_data.py:
python minor_planner/generate_checker_data.py --year 2025_26
# After editing generate_checker_page.py or after regenerating checker_data.json:
python minor_planner/generate_checker_page.py --year 2025_26
# After editing generate_minor_site.py:
python minor_extraction/generate_minor_site.py --year 2025_26
```

## Hardcoded constants in generate_checker_data.py
- `AREA_CODE_LISTS` — Music Area 2B/2C course suffixes (64 codes)
- `EQ_NOTES` — Equivalence tables for CS, Statistics, RMS, Physics
- `AND_EQ_GROUPS` — Multi-course AND equivalences (Statistics, RMS)
- `SUBJ_BUCKETS_NOTES` — Physics max 6u equivalent course bucket
- `KNOWN_GROUPS` — Faculty prefix grouping for E&I cap

## Auto-detection from explanatory notes
- `detect_notes_eq_rules()` scans raw notes HTML for:
  - `"X is equivalent to Y"` → eq_pairs
  - `"passed X are exempted from Y"` → waiver_rules
  - `"have taken X will be recognized as having fulfilled this requirement [and N units of elective]"` → eq_pairs + credit waiver
  - `"not more than N units … same Faculty"` → faculty_caps

## Course info JSON format
- Each `course_extraction/course_info/<DEPT>.json` is an array of:
  ```json
  {
    "code": "DEPT 1234", "title": "...", "unit": "3.00", "info": "...",
    "term_1": true, "term_2": true, "term_offerings": [],
    "sections": [{"term_code": "2420", "term": "2026-27 Term 1", "section": "A-LEC", "component_type": "LEC", "class_number": "9700", "status": "Open", "class_capacity": "100", "wait_list_capacity": "0", "enrollment_total": "90", "wait_list_total": "0", "available_seats": "10", "timetable": [{"day_time": "Mo 12:30PM - 2:15PM", "room": "...", "instructor": "...", "dates": "..."}]}]
  }
  ```
- `term_1`/`term_2` indicate whether any section `term` label contains an academic year followed by `Term 1`/`Term 2` (for example, `2026-27 Term 1`).
- Each term/section appears once; its individual meeting rows are stored in `timetable`.

## Chip coloring rules (checker page)
- **Green** — course consumed by THIS row (in `row.consumedCodes`)
- **Yellow** — course consumed by a DIFFERENT row, or surplus not used anywhere
- **Red** — equivalence match (student has equivalent, not exact code)
- **Gray** — waived course (replacement not yet taken)
- When subject bucket constraints cap earned, truncate `consumedCanon` so excess courses show yellow.
